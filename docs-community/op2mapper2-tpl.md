# OP2Mapper2 code templates (`.tpl`)

OP2Mapper2 is the classic Outpost 2 map editor, written in Visual Basic 6 by BlackBox and Hooman (2.0 alpha released
in 2005; the source read here is marked 2.2.4 in its project file). Its code generator turns the units and objects
placed on a map (its [`.map.dat`](op2mapper2-map-dat.md)) into C++ source for a mission DLL, from a template: a `.tpl`
file in the mapper's folder. The template is ordinary text with section keywords and `$` variables. The game never
reads it.

## Generating code

The generate dialog lists every `*.tpl` in the mapper's folder and asks for an output file (by default the map's path
with `.cpp` added, `eden04.map.cpp`). The output replaces any existing file and is written as plain bytes in the
system's ANSI code page, with CRLF line ends. If anything goes wrong while generating, the mapper says "TPL Parser
error occurred." and writes nothing.

## Sections

The file is read line by line. A line whose whole text, trimmed and in any case, is one of these keywords starts a
section; every other line is added, unchanged and with its indentation, to the current section:

| Keyword | Section |
|---|---|
| `$$begin` | prolog: written once, first |
| `$$player` | player prolog: written at the start of each player |
| `$$unit` | written once per unit of the player |
| `$$endplayer` | player epilog: written at the end of each player |
| `$$beacon` | written once per Gaia object of type 0 |
| `$$wall` | written once per Gaia object of type 1 |
| `$$wreck` | written once per Gaia object of type 2 |
| `$$end` | epilog: written once, last |
| `$$rem` | a comment line |

- A section can have any number of lines, and a keyword may appear again: its lines are added to the same section.
- Lines before the first keyword are ignored.
- Only a line that is exactly `$$rem` is a keyword. A `$$rem` line with text after it is an ordinary line: ignored
  before the first section, like any line there, but **copied to the output** inside a section.
- A section that is left out is empty; for example, a template without `$$beacon` writes nothing for beacons.

The object types are those of [`objects.ctl`](op2mapper2-objects-ctl.md). For an object whose type is none of 0, 1 or
2 the generator writes again the text it wrote just before (the prolog for the first object, else the previous
object's).

## Output order

1. A header, always:
   ```
   // Generated by OP2Mapper <version>
   // at <date and time>
   // using template <full path of the .tpl>
   // Total Number of Objects: <number of records>
   ```
   then an empty line. The version is the program's (major.minor.revision), the date and time in Windows' format.
2. The prolog.
3. Each Gaia object's section, in the order they were placed.
4. For each player from 0 to `$playersused` − 1: the player prolog, then the `$$unit` section for each of that
   player's units in the order they were placed, then the player epilog.
5. The epilog.

**Players.** `$playersused` is 1 plus the number of players from 1 upwards that have a unit, counted until the
first that has none. Player 0 is always written, even with no units; a player after a gap is not written at all, so
with units for players 0 and 2 only, player 2's units are left out of the code.

## Variables

Each variable is replaced as plain text, in any case, wherever it appears, including inside a longer word (`$xpos`
becomes `11pos`). A variable a section doesn't list stays as written.

| Variable | Value | Sections |
|---|---|---|
| `$totalunits` | the number of records, units and objects | all |
| `$playersused` | the number of players written (above) | all |
| `$template` | the full path of the template file | all |
| `$mapname` | the map's file name without its folder (`eden04.map`; `Untitled1` for an unsaved map) | all |
| `$playerid` | the player's number, 0 to 6 | player prolog and epilog, `$$unit` |
| `$playerunits` | the number of that player's units | player prolog and epilog, `$$unit` |
| `$mapid` | the unit's or object's `map_id` | `$$unit`, Gaia sections |
| `$weaponmapid` | the unit's weapon `map_id`, 0 for none | `$$unit` |
| `$x` | the tile column + 1 | `$$unit`, Gaia sections |
| `$y` | the tile row + 1 | `$$unit`, Gaia sections |
| `$extra1`-`$extra3` | the object's extras from `objects.ctl` | Gaia sections |
| `$gaiaunits` | 1 if the map has any Gaia object, else 0 | Gaia sections |

`$gaiaunits` reads like a count of the Gaia objects, but the counting loop stops at the first one, so it is never
more than 1.

The variables are replaced in this order, so a value containing a later variable's name would be replaced again:
`$totalunits`, `$playersused`, `$template`, `$mapname`, then for units `$playerid`, `$playerunits`, `$mapid`,
`$weaponmapid`, `$x`, `$y`, and for objects `$mapid`, `$x`, `$y`, `$extra1`-`$extra3`, `$gaiaunits`.

**Coordinates.** `$x` and `$y` count tiles from 1. The shipped templates write `LOCATION($x+31, $y-1)`, which is the
column + 32 and the row: the game's coordinates on maps that don't wrap ([maps.md](../docs/maps.md#coordinates)). They
add the 32 on 512-wide maps too, where the game doesn't.

## The shipped templates

- **`Default.tpl`**: a `SetupObjects()` function. Gaia objects come first; each player's units are in an
  `if (TethysGame::NoPlayers() > $playerid)` block, written with `CreateUnit`, `CreateBeacon`, `CreateWallOrTube`
  and `CreateWreck`.
- **`Generic LoS.tpl`**: a whole Last One Standing mission DLL (`DllMain`, `InitProc` and the other exports) with
  starting kits, research, morale and day and night set up, and the players' places shuffled with `RandomizeList`.
  It has `$$rem` lines with text inside its sections, so by the rules above its output contains them and won't compile
  until they are removed (from the source, not tried in the running mapper).
- **`hooville.tpl`**: a `SetupUnits()` function with `$$unit` lines only; objects write nothing.

## Writing one

Put each keyword on a line of its own, and comments as a bare `$$rem` line or outside any section (`$$rem` with text
is safe only before the first keyword). Give `$$beacon`, `$$wall` and `$$wreck` sections if the map has objects, and
remember that player numbers must run without gaps.
